# คำสั่ง `/tasks` (agent-pack v2)

## ขั้นตอนการทำงาน
1. อ่าน `AGENTS.md` และปฏิบัติตามกติกาทั้ง 10 ข้อ (**ห้ามอ่าน** `docs/hand-written/`)
2. อ่าน `spec.md`, `*.feature`, `rules.md`, `models.md`, `mockups/`, `plan.md` และ `specs/000-shared/constraints.md`
3. หากมีไฟล์ `tasks.md` อยู่แล้ว ให้หยุดถามทีมก่อนว่าจะให้เพิ่ม/แก้เฉพาะ Task ตาม `CR` หรือสร้างใหม่ ห้ามเขียนทับทั้งไฟล์โดยไม่ถาม

## โครงสร้างไฟล์ `tasks.md`
แบ่งงานเป็น `T-01`, `T-02`, ... เรียงตามลำดับที่ต้องทำก่อน-หลัง โดยแต่ละ Task ต้องมีครบ **6 ช่อง**:
1. **ทำอะไร:** คำอธิบายสั้นและชัดเจนว่าสร้างหรือแก้ส่วนใด
2. **สร้างหรือแก้ไฟล์ไหน:** ระบุ path ของไฟล์ทุกไฟล์ที่อนุญาตให้แตะใน Task นี้
3. **ต้องทำหลัง:** ระบุรหัส `T-xx` ที่ต้องเสร็จก่อน (หรือ `ไม่มี` สำหรับ `T-01`)
4. **รองรับ REQ / AC:** ระบุรหัส `REQ-xx`, `AC-xx`, `BR-xx`, `CC-xx`, `UI-xx`
5. **เสร็จเมื่อ (Definition of Done):** เกณฑ์ที่ตรวจได้จริง เช่น ชื่อฟังก์ชัน test (`test_AC_xx_nn`) ที่ต้องรันผ่าน
6. **ยังติดคำถาม (`Q-xx` / `AS-xx`):** ระบุคำถามเปิดหรือสมมติฐานที่เกี่ยวข้อง (ถ้าไม่มีให้เขียน `ไม่มี`)

## ตารางตรวจสอบท้ายไฟล์ `tasks.md` (บังคับมีครบ 2 ตาราง)
1. **ตารางตรวจความครบของ AC (Two-way Traceability):** ไล่ `AC` ทุกข้อใน `spec.md` / `.feature` ว่าอยู่ใน `T-xx` ใด และตรวจด้วย test ชื่ออะไร (ต้องไม่มี `AC` ตกหล่นแม้แต่ข้อเดียว)
2. **ตารางตรวจความครบของ Constraints:** ไล่ Constraint ทุกข้อจาก `specs/000-shared/constraints.md` ว่าอยู่ใน `T-xx` ใด

สุดท้าย บันทึกการทำงานลงใน `prompt-log.md`
