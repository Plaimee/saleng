# ฝั่งผู้ดูแลระบบ ลำดับที่ 3: ศูนย์ควบคุมการจับคู่งานและข้อพิพาท (`3. ศูนย์ควบคุมการจับคู่งานและข้อพิพาท`)

- **อ้างอิงอาร์ติแฟกต์ที่เกี่ยวข้อง:**
  - ตารางแบ่งฟีเจอร์ฝั่ง **`ผู้ดูแลระบบ`** ลำดับที่ **`3`**
  - Use Case Diagram: **`UC-13: จัดการข้อพิพาทและงานตกค้าง`**
  - State Machine: **`MD-STM-04` สถานะ `S9: ระงับชั่วคราว / ข้อพิพาท (Disputed / Frozen)` และ Events `E9, E10`**
  - ความต้องการที่เกี่ยวข้อง: `REQ-FN-005` (การยืนยันน้ำหนักสองฝ่าย `Dual-party Weight Confirmation`), `BR-02` (คำขอที่ไม่มีซาเล้งรับภายในเวลาที่กำหนด)

---

## 1. ขอบเขตการทำงาน (Feature Scope)

1. **ระบบกระจายงานกรณีสำรอง (`Manual Dispatch Fallback`):**
   - แทรกแซงและช่วยกระจายงานไปยังซาเล้งในพื้นที่ด้วยตนเอง เมื่ออัลกอริทึมจับคู่อัตโนมัติ (`AI Agent` / ระบบค้นหาตามเส้นทาง) ไม่สามารถหาคนขับได้ภายในเวลาที่กำหนด (งานตกค้างตาม `UC-13` และ `BR-02 Inference` หน้า 62)
2. **ศูนย์จัดการข้อพิพาทหน้างาน (`Dispute Resolution`):**
   - รับเรื่องร้องเรียน (`E9 -> S9: ระงับชั่วคราว / ข้อพิพาท`) ตรวจสอบภาพถ่ายกองขยะ (`REQ-FN-004`) หลักฐานเสียง/วิดีโอ และประวัติการยืนยันน้ำหนักสองฝ่าย (`Dual-party Weight Confirmation` ตาม `REQ-FN-005`) เพื่อไกล่เกลี่ยข้อพิพาทเรื่องราคากับน้ำหนักจริง
   - แอดมินสามารถตัดสินให้จบงาน (`E10: Admin ตัดสินให้จบงาน -> S7`) หรือสั่งยกเลิก/คืนเงิน (`E10: Admin สั่งยกเลิก/คืนเงิน -> S8`) ตามผังสถานะหน้า 63

---

## 2. เกณฑ์การยอมรับ (`Acceptance Criteria`)
- **`AC-A03-01` (`Manual Dispatch Fallback` — `UC-13`):** เมื่อมีคำขอสถานะ `S2 (รอผู้รับซื้อ)` ตกค้างเกินเวลาที่กำหนด แอดมินสามารถดูรายการงานตกค้างและกดกระจายงานไปยังซาเล้งในพื้นที่หรือขยายรัศมีค้นหาได้
- **`AC-A03-02` (`Dispute Resolution` — `UC-13`, `REQ-FN-005`, `S9`):** เมื่อเกิดข้อพิพาท (`S9`) แอดมินสามารถเปิดดูภาพถ่ายของเก่า ประวัติตัวเลขน้ำหนักสองฝ่าย และกดตัดสินชี้ขาดให้จบงาน (`-> S7`) หรือยกเลิกคำขอ (`-> S8`) ได้
