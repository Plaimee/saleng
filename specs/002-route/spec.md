## 1. Intent (เจตนา)
ซาเล้ง (ผู้รับซื้อของเก่า) ต้องการเห็นคำขอขายของเก่าที่อยู่ในเส้นทางที่กำลังจะผ่าน (ในรัศมีไม่เกิน 5 กม.) เพื่อไม่ต้องขับรถเปล่าหรือพลาดงานใกล้ตัว (`EV-003`, `EV-004`, `EV-012`)
ผู้ขายต้องการให้มีซาเล้งมารับจริงภายในเวลาที่สมเหตุสมผล พร้อมความน่าเชื่อถือและความปลอดภัยในการเรียกซาเล้งมาถึงบ้าน (`EV-001`, `EV-002`, `SC-01`, `SC-04`) และเจ้าของธุรกิจต้องการอัตราการจับคู่งานสำเร็จสูงขึ้น ลดจำนวนคำขอที่ไม่มีใครรับ (`UC-04: Stakeholders and Interests`)

## 2. Scope & Non-goals (ขอบเขตและสิ่งที่จงใจไม่ทำใน `UC-04`)

### In Scope (`UC-04` เริ่มที่ Trigger และจบที่ Postcondition):
- อ่านตำแหน่งปัจจุบันของซาเล้งจาก `GPS`
- ค้นหาคำขอขายสถานะ `"รอผู้รับงาน"` (`Pending / S2`) ในรัศมีที่กำหนด (ค่าตั้งต้น `5 กม.`)
- แสดงรายการคำขอ พร้อมระยะทาง ราคาประเมิน และประเภทของ
- ดูรายละเอียดคำขอหนึ่งรายการ
- กดรับงาน ผูกคำขอกับซาเล้ง และเปลี่ยนสถานะเป็น `"มีผู้รับงานแล้ว"` (`Assigned / S3`)
- แจ้งเตือนผู้ขายเมื่อมีผู้รับงาน
- ทางเลือกและข้อยกเว้น `A1`, `A2`, `E1`, `E2`, `E3` (ดูหัวข้อที่ 5)

### Non-goals (จงใจไม่ทำใน `UC-04` แต่แยกอยู่ในฟีเจอร์อื่น):
- **การยืนยันตัวตนซาเล้ง (`Thai-ID / DBD-ID` — `SC-04`):** เป็นเงื่อนไขก่อนเริ่ม (`Precondition`) ที่ทำใน `UC-01` ([`specs/buyer/01-account-and-kyc/spec.md`](../buyer/01-account-and-kyc/spec.md)) โดย `UC-04` ทำแค่ตรวจว่าบัญชี `"อนุมัติแล้ว"` (`saleng.verified == true`) ก่อนให้กดรับงาน
- **การนำทางแบบเลี้ยวต่อเลี้ยว (`Turn-by-turn`) และการติดตามการเดินทาง (`UC-09`):** เกิดหลังสถานะ `"มีผู้รับงานแล้ว"` (`S4: กำลังเดินทาง`) แยกไว้ใน [`specs/buyer/04-job-and-route-management/spec.md`](../buyer/04-job-and-route-management/spec.md)
- **การชั่งน้ำหนัก การชำระเงิน และการยกเลิกหลังรับงาน:** อยู่ใน `UC-06`, `UC-10`, `UC-12`, `UC-13` (`State S4 ถึง S9` ของ Order)
- **การสร้างคำขอขายและการตรวจมูลค่าขั้นต่ำ (`REQ-FN-001`):** เป็นงานต้นทางฝั่งผู้ขาย ([`specs/seller/02-scrap-posting/spec.md`](../seller/02-scrap-posting/spec.md) และ [`specs/seller/04-pricing-and-decision/spec.md`](../seller/04-pricing-and-decision/spec.md)) โดย `UC-04` รับมาเฉพาะคำขอที่ผ่านแล้ว
- **Out of Scope R1 (`SC-06..08`):** ยังไม่ทำผู้ใช้แบบนิติบุคคล (`SC-06`), โลจิสติกส์ระดับโรงงาน (`SC-07`), และคัดแยกขยะอัตโนมัติด้วย AI/Hardware (`SC-08`)

## 5. Behaviour (ลำดับขั้นตอนและข้อยกเว้น)

### Main Success Scenario (`UC-04` — 7 ขั้นตอน):
1. ซาเล้งเปิดแอปและเข้าหน้ารายการนัดหมาย (`"รายการนัดหมายในเส้นทาง"`)
2. ระบบอ่านตำแหน่งปัจจุบันของซาเล้งจาก `GPS`
3. ระบบค้นหารายการคำขอขายของเก่าในรัศมีที่กำหนด (`5 กม.`) จากตำแหน่งซาเล้ง
4. ระบบแสดงรายการคำขอ พร้อมระยะทาง ราคาประเมิน และประเภทของที่จะขายกำกับแต่ละรายการ
5. ซาเล้งเลือกดูรายละเอียดคำขอที่สนใจ
6. ซาเล้งกดรับงาน
7. ระบบเปลี่ยนสถานะคำขอเป็น `"มีผู้รับงานแล้ว"` (`S3`) และแจ้งเตือนผู้ขายทันที

### Extensions (เรียบเรียงจาก `MD-ACT-04` และ `MD-SEQ-04`):

| รหัส | เงื่อนไข | พฤติกรรมของระบบ (ตรง) |
| :---: | :--- | :--- |
| **`A1`** | ไม่พบคำขอในรัศมี | แสดง `"ยังไม่มีงานในเส้นทาง"` และเสนอให้ขยายรัศมีเป็น `10 กม.` ถ้าซาเล้งไม่ขยาย จบที่สถานะรอ (`Pending`) |
| **`A2`** | ซาเล้งปฏิเสธหรือข้ามงานหลังดูรายละเอียด | กลับไปหน้ารายการ คำขอยังเป็น `"รอผู้รับงาน"` (`Pending`) |
| **`E1`** | ไม่มีสัญญาณ `GPS` หรือไม่ได้อนุญาตตำแหน่ง | แจ้งให้เปิด `GPS` หรืออนุญาตตำแหน่ง ไม่แสดงรายการที่คำนวณจากตำแหน่งเก่า (`Postcondition Failure: บล็อกการแสดงรายการ`) |
| **`E2`** | ซาเล้งอื่นรับงานไปก่อน (กดพร้อมกัน) | แจ้ง `"มีผู้รับงานแล้ว"` และรีเฟรชรายการ ไม่ผูกงานกับซาเล้งคนนี้ |
| **`E3`** | `Maps API` ไม่ตอบสนอง | แจ้งว่าคำนวณระยะทางไม่ได้ชั่วคราว ให้ลองใหม่ ไม่แสดงระยะทางที่ไม่ได้คำนวณจริง |

## 8. Open Questions (`Q-01..Q-06`), Consistency Checks (`CC-01..CC-06`) & Decision Log (`D-01..D-03`)

### 8.1 คำถามเปิด (`Open Questions`)
- **`Q-01`:** ซาเล้งสองคนกดรับพร้อมกันในเสี้ยววินาที ระบบตัดสินด้วยอะไร (เวลาที่ถึง Server ก่อน หรือคะแนนรีวิวสูงกว่า) — *ค่าชั่วคราว: First-come เวลาที่ถึง Server ก่อน*
- **`Q-02`:** `"รัศมี 5 กม."` วัดเป็นเส้นตรงหรือระยะทางตามถนน — *ออกแบบ 2 ชั้นใน `P-01`: กรองเส้นตรงก่อนแล้วคำนวณตามถนน*
- **`Q-03`:** ซาเล้งหนึ่งคนถือหลายงานพร้อมกันได้หรือไม่ (`BR-02` คุมแค่ `"หนึ่งคำขอ หนึ่งซาเล้ง"`)
- **`Q-04`:** เก็บตำแหน่งซาเล้ง (`Saleng.currentLocation`) นานเท่าไรตาม PDPA
- **`Q-05`:** `"แจ้งเตือนผู้ขายทันที"` ต้องถึงภายในกี่วินาที — *ตั้งเป้าชั่วคราว 60 วินาที*
- **`Q-06`:** ภาระระบบที่ต้องรองรับ (`Concurrent 200` ใน `TASKS v2.0` ต้องยืนยัน)

### 8.2 ความไม่สอดคล้องที่พบและข้อเสนอแก้ไข (`CC-01..CC-06`)
- **`CC-01`:** `BR-02` มี 3 ความหมายในบอร์ด -> **ข้อเสนอ:** ยึดความหมายตาม `UC-04` (`"หนึ่งคำขอ หนึ่งซาเล้ง"`)
- **`CC-02`:** `UC-04` อ้าง `REQ-OP-002` แต่การ์ด Offline ของกลุ่มคือ `REQ-OP-001` -> **ข้อเสนอ:** เปลี่ยน `UC-04` ให้อ้าง `REQ-OP-001` คู่กับ `REQ-OP-002`
- **`CC-03`:** `"15%"` มี 2 ความหมาย (ความแม่นยำระยะทาง vs `detourPercentage <= 15%`) -> **ข้อเสนอ:** ยึดตาม `UC-04` (ความแม่นยำระยะทาง `<= 15%`) ส่วน `detourPercentage` เป็นค่าที่บันทึกไว้
- **`CC-04`:** `REQ-BR-002`, `REQ-QA-002`, `REQ-SEC-002` ถูกอ้างใน `PLAN/TASKS` -> **ข้อเสนอ:** เพิ่มเข้า Catalogue ก่อนประกาศ `B1`
- **`CC-05`:** ชื่อหน้าจอไม่ตรงกัน -> **ข้อเสนอ:** ใช้ชื่อตาม `UC-04` คือ `"รายการนัดหมายในเส้นทาง"`
- **`CC-06`:** Extension `A2` ไม่มีคำอธิบายในบอร์ด -> **ข้อเสนอ:** เขียนคำอธิบาย `A2` ใน `UC-04` (ซาเล้งปฏิเสธหรือข้ามงานหลังดูรายละเอียด)

### 8.3 บันทึกการตัดสินใจ (`Decision Log D-01..D-03`)
- **`D-01`:** `Thai-ID / DBD-ID` เป็น `Precondition` ไม่ใช่งานใน `UC-04` (ปฏิเสธการเชื่อมต่อ Thai-ID ซ้ำในฟีเจอร์นี้) และเกณฑ์ส่วนต่างน้ำหนักชั่งจริงกำหนดที่ `±15%` (`BR-02`)
- **`D-02`:** ซ่อนพิกัดผู้ขายจนกว่าจะรับงาน (ปฏิเสธการส่งพิกัดจริงตั้งแต่หน้าค้นหา) และคิวออฟไลน์เก็บสูงสุด 50 รายการ / 24 ชม.
- **`D-03`:** หยุด `UC-04` ที่ `"มีผู้รับงานแล้ว"` สำหรับส่วนค้นหา และใช้ Haversine Fallback เมื่อระบบแผนที่ภายนอกไม่ตอบสนอง
