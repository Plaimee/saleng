# คู่มือการสร้างและตรวจหน้าจอ Mockup (`docs/mockup-guide.md`)

ตามกติกาข้อ 10 ของ [`AGENTS.md`](../AGENTS.md) หน้าจอต้นแบบในโฟลเดอร์ `mockups/` ของแต่ละฟีเจอร์ใช้สื่อสารโครงหน้าจอและข้อความสำคัญระหว่างทีม ผู้มีส่วนได้เสีย (`SH-xx`) และ AI

---

## 1. กฎการเขียนไฟล์ HTML Mockup
1. **จบในไฟล์เดียว (Single-file Static HTML):** ใช้ HTML + CSS ในไฟล์เดียว เปิดดูในเบราว์เซอร์ได้ทันทีโดยไม่ต้องรันเซิร์ฟเวอร์
2. **ระบุ `data-req` ที่องค์ประกอบหลัก:** ทุกส่วนสำคัญบนหน้าจอต้องติดแอตทริบิวต์ `data-req="REQ-..."` หรือ `data-req="BR-..."` เพื่อผูกสายตามรอยใน `rtm.md`
3. **ล้อมกรอบคำถามเปิดด้วย `.todo`:** หากส่วนใดของหน้าจอยังเป็นคำถามเปิด (`Q-xx`) หรือสมมติฐานที่ยังไม่อนุมัติ (`AS-xx`) ให้ใส่คลาส `class="todo"` ตีกรอบเส้นประสีส้ม AI จะรับรู้ทันทีว่า **ห้ามสร้างส่วนนี้ในโค้ดจริง**

---

## 2. รายการตรวจหน้าจอ 6 ข้อ (`ui-review.md`)
ทุกครั้งหลังจบงานหน้าจอ ให้ทีมเปิดหน้าจอที่สร้างจริงเทียบกับไฟล์ใน `mockups/` แล้วตรวจครบ 6 ข้อ:
1. โครงหน้าจอและลำดับขั้นตอนตรงกับ Mockup
2. ป้ายข้อความภาษาไทยและหน่วยนับตรงตาม `docs/srs/glossary.md`
3. แอตทริบิวต์ `data-req` ครบทุกองค์ประกอบหลัก
4. ไม่สร้างฟีเจอร์ที่อยู่ใน `Non-goals`
5. ไม่สร้างส่วนที่อยู่ในกรอบ `.todo` (`Q-xx`)
6. ความเหมาะสมต่อบริบทผู้ใช้ (เช่น ปุ่มขนาด `>= 48px` ตาม `REQ-UX-001` และการปกปิดข้อมูลตาม `REQ-SEC-002`)
