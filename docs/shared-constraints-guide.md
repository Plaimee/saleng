# คู่มือการจัดการไฟล์ Constraint กลาง (`docs/shared-constraints-guide.md`)

ตามกติกาข้อ 9 ของ [`AGENTS.md`](../AGENTS.md) ข้อจำกัดทางเทคนิค ความปลอดภัย ความเป็นส่วนตัว และการปฏิบัติการที่ใช้ร่วมกันทุกฟีเจอร์ในระบบ ต้องเก็บไว้ที่เดียวคือ [`specs/000-shared/constraints.md`](../specs/000-shared/constraints.md)

## กฎเหล็ก 3 ข้อของ Constraint กลาง
1. **เขียนที่เดียว อ้างอิงด้วยรหัส:** ใน `spec.md` ของแต่ละฟีเจอร์ (เช่น `specs/002-route/spec.md` หรือ `specs/seller/*`) ให้อ้างอิงเฉพาะรหัส เช่น `CC-01..06`, `REQ-SEC-001..002`, `REQ-OP-001..002` ห้ามคัดลอกย่อหน้าเต็มไปวางซ้ำ
2. **ห้าม AI แก้ไฟล์กลางเอง:** หากระหว่างทำ `/clarify` หรือ `/plan` พบว่าควรเพิ่มหรือปรับข้อจำกัดกลาง ให้เสนอเป็นคำถามและออกใบขอเปลี่ยนแปลง (`CR`) เช่น [`changes/CR-04.md`](../changes/CR-04.md)
3. **ตรวจครบทุกข้อใน `plan.md`:** ตารางส่วนที่ 8 ของ `plan.md` ต้องนำรหัสใน `specs/000-shared/constraints.md` มาแสดงครบทุกข้อ หากข้อใดไม่เกี่ยวกับฟีเจอร์นั้น ต้องเขียนเหตุผลชัดเจนว่า `"ไม่เกี่ยวกับ feature นี้ เพราะ..."` ห้ามลบแถวทิ้ง
