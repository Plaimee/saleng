# ตารางจำแนกระดับความรุนแรงของข้อบกพร่องและ SLA การแก้ไข (`docs/acceptance/severity-matrix.md`)

เอกสารนี้กำหนดเกณฑ์การจัดระดับความรุนแรงของข้อบกพร่อง (Defect Severity Classification `S1..S4`) และเงื่อนไขการตรวจรับสำหรับโครงการ Saleng (กลุ่ม 2)

---

## ตารางระดับความรุนแรงของข้อบกพร่อง (`S1` ถึง `S4`)

| ระดับความรุนแรง | ชื่อระดับ | คำจำกัดความและตัวอย่างในระบบ Saleng | ผลต่อการลงนามตรวจรับ (UAT Gate) | ระยะเวลาแก้ไขเป้าหมาย (SLA) |
|---|---|---|---|---|
| **`S1`** | **วิกฤต (Blocker / Critical)** | ระบบหลักใช้งานไม่ได้ ข้อมูลสูญหาย คำนวณยอดเงินผิดพลาด หรือข้อมูลส่วนบุคคลรั่วไหล เช่น:<br>- น้ำหนักต่างเกิน `±15%` แต่ระบบข้ามไปคิดเงินโดยไม่ถามผู้ขาย (`BR-02` ผิดพลาด)<br>- คิวออฟไลน์ซิงก์แล้วสร้างใบเสร็จซ้ำซ้อน (`REQ-OP-001` ล้มเหลว)<br>- เปิดเผยบ้านเลขที่จริงของผู้ขายให้บุคคลทั่วไปเห็นในสถานะ `S1` (`REQ-SEC-002` รั่วไหล) | **ห้ามตรวจรับเด็ดขาด (Reject)** ต้องแก้ไขและรัน Regression Test ใหม่ทั้งชุดจนผ่าน 100% | ภายใน `4 ชั่วโมง` |
| **`S2`** | **รุนแรง (Major / High)** | ฟีเจอร์สำคัญทำงานไม่สมบูรณ์หรือระบบสำรองไม่ทำงานตามเกณฑ์คุณภาพ เช่น:<br>- เมื่อ Maps API ล่ม ระบบไม่สลับไปใช้สูตรสำรอง Haversine (`REQ-OP-002`) หรือใช้เวลานานเกิน `2.0 วินาที` (`REQ-QA-001`)<br>- ไม่สามารถแนบรูปถ่ายหน้าตาชั่งขนาด `< 1 MB` ได้ | **ชะลอการตรวจรับ (Hold)** จนกว่าจะแก้ไขเสร็จในรอบส่งมอบเดียวกัน | ภายใน `24 ชั่วโมง` |
| **`S3`** | **ปานกลาง (Minor / Medium)** | การทำงานหลักถูกต้องครบถ้วน แต่ความสะดวกในการใช้งานไม่ตรงตามเกณฑ์รอง เช่น:<br>- ปุ่มกดบนหน้าจอมือถือของซาเล้งมีความสูงน้อยกว่า `48px` (`REQ-UX-001` — พบใน `GAP-05` และแก้ไขแล้ว) | **ตรวจรับแบบมีเงื่อนไขได้ (Conditional Accept)** หากมีไม่เกิน 2 ข้อและมีกำหนดวันแก้ไขชัดเจน | ภายใน `3 วันทำการ` |
| **`S4`** | **เล็กน้อย (Cosmetic / Trivial)** | ความสวยงามของตัวอักษร ระยะห่างขอบ หรือคำผิดเล็กน้อยที่ไม่กระทบความเข้าใจและไม่กระทบการคำนวณ | **ตรวจรับได้ทันที (Accept)** และนำไปเก็บงานใน Sprint ถัดไป | ภายใน `7 วันทำการ` (หรือ Release ถัดไป) |
