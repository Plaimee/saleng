# ทะเบียนหลักฐานจากการสำรวจความต้องการ (`docs/srs/evidence.md`) — โครงการ Saleng (กลุ่ม 2)

เอกสารนี้รวบรวมหลักฐานต้นทาง (`EV-01..EV-09`) จากการสัมภาษณ์ซาเล้ง ผู้ขายครัวเรือน ลานรับซื้อ และการสำรวจหน้างานจริง ซึ่งใช้เป็นต้นทางของสายตามรอย (`EV -> REQ -> AC`)

---

## ตารางทะเบียนหลักฐาน (`EV-01` ถึง `EV-09`)

| รหัสหลักฐาน | แหล่งที่มา / ผู้ให้ข้อมูล (`SH-xx`) | วิธีการเก็บข้อมูล | ข้อเท็จจริงที่พบจากหน้างาน (Observation / Quote) | ความต้องการที่แตกออกมา (`REQ-ID`) |
|---|---|---|---|---|
| `EV-01` | ซาเล้งรับซื้อของเก่า 5 รายในเขตกรุงเทพฯ (`SH-01`) | สัมภาษณ์เชิงลึกและติดตามสังเกตการณ์หน้างาน | *"เวลาขี่ซาเล้งมือหนึ่งจับแฮนด์ อีกมือดูมือถือกลางแดดจ้า ถ้าปุ่มเล็กหรือต้องพิมพ์เยอะจะกดไม่ถนัด และตามซอยลึก ๆ เน็ตชอบหลุดตอนกำลังจดน้ำหนัก"* | `REQ-FN-001`, `REQ-OP-001`, `REQ-UX-001`, `REQ-UX-002`, `REQ-QA-002` |
| `EV-02` | ซาเล้งรับซื้อของเก่า (`SH-01`) | สัมภาษณ์และวิเคราะห์เส้นทางวิ่งรถ | *"อยากเห็นงานที่อยู่ในรัศมี 5 กม. เรียงตามทางผ่าน และถ้ารถเต็ม 200 กก. แล้วไม่อยากให้ระบบส่งงานใหญ่เข้ามาซ้อนในรอบเดียว"* | `REQ-FN-001`, `REQ-FN-003`, `REQ-OP-002`, `REQ-QA-001`, `BR-03` |
| `EV-03` | ผู้ขายของเก่าตามครัวเรือน 8 ราย (`SH-02`) | สัมภาษณ์และแบบสอบถามปัญหาการขายของเก่า | *"เวลาประเมินน้ำหนักจากรูปถ่ายเองที่บ้านมักกะไม่แม่น พอซาเล้งมาชั่งจริงหน้าบ้านแล้วน้ำหนักต่างกัน อยากเห็นรูปถ่ายหน้าตาชั่งชัด ๆ ในแอป"* | `REQ-FN-002`, `REQ-DAT-001`, `REQ-UX-002` |
| `EV-04` | ตัวแทนซาเล้ง (`SH-01`) และผู้ขาย (`SH-02`) | ประชุมกลุ่มย่อยหาข้อตกลงร่วม (Workshop) | *"ถ้าน้ำหนักชั่งจริงบวกลบไม่เกิน 15% จากที่ประเมินไว้ คิดเงินตามน้ำหนักจริงได้เลยไม่ต้องเสียเวลากดยืนยันซ้ำ แต่ถ้าต่างเกิน 15% ต้องเด้งให้คนขายกดตกลงยอดใหม่ก่อน"* | `REQ-FN-002`, `REQ-FN-004`, `REQ-FN-006`, `REQ-BR-002`, `BR-02` |
| `EV-05` | ผู้ขายของเก่า (`SH-02`) และลานรับซื้อ (`SH-03`) | สัมภาษณ์ขั้นตอนการชำระเงินและส่งต่อวัสดุ | *"อยากได้ใบเสร็จดิจิทัลที่ระบุน้ำหนักจริง ราคาต่อกิโลกรัมที่ล็อกไว้ตอนนัดหมาย และยอดเงินสุทธิ เพื่อใช้อ้างอิงทั้งคนขายและเวลาซาเล้งเอาของไปส่งลาน"* | `REQ-FN-004`, `REQ-FN-005`, `REQ-BR-002`, `BR-01` |
| `EV-06` | เจ้าของลานรับซื้อของเก่าพันธมิตร (`SH-03`) | สัมภาษณ์เชิงธุรกิจ | *"ราคากลางขวดพลาสติกและกระดาษลังปรับขึ้นลงระหว่างวันได้ ถ้าตกลงนัดหมายกันตอนเช้าแล้วต้องยึดราคาตอนที่นัดหมาย ไม่อย่างนั้นซาเล้งกับคนขายจะเถียงกันหน้าบ้าน"* | `REQ-BR-002`, `REQ-FN-005`, `REQ-DAT-001`, `BR-01` |
| `EV-07` | ทีมวิศวกรรมและฝ่ายปฏิบัติการ (`SH-04`, `SH-08`) | ทดสอบสัญญาณเครือข่ายและ API แผนที่ภายนอก | *"เมื่อจำลองสัญญาณ 4G ขาดหายแล้วเชื่อมต่อใหม่ แอปอาจส่งคำขอออกใบเสร็จซ้ำ 2 ครั้ง และเมื่อ OSRM API ตอบช้าเกิน 2 วินาที ต้องมีสูตรคำนวณระยะทางสำรองทันที"* | `REQ-OP-001`, `REQ-OP-002`, `REQ-QA-001`, `REQ-QA-002` |
| `EV-08` | ผู้ขายของเก่า (`SH-02`) และผู้ดูแลระบบ (`SH-04`) | สัมภาษณ์ด้านความปลอดภัยและข้อพิพาท | *"ไม่อยากให้โชว์บ้านเลขที่จริงและเบอร์โทรเต็ม ๆ ในหน้าค้นหาสาธารณะ ให้เห็นเฉพาะซอยหรือจุดสังเกตจนกว่าซาเล้งที่ผ่าน KYC จะกดรับงาน และถ้ามีปัญหาต้องล็อกรูปตาชั่งไว้ห้ามแก้"* | `REQ-FN-006`, `REQ-SEC-001`, `REQ-SEC-002` |
| `EV-09` | ข้อกำหนดกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA — `SH-06`) | ทบทวนข้อกฎหมายและนโยบายความเป็นส่วนตัว | *"ข้อมูลพิกัดที่พักอาศัยและหมายเลขโทรศัพท์ถือเป็นข้อมูลส่วนบุคคล ต้องทำ Data Masking เมื่อยังไม่เกิดธุรกรรมและหลังจากธุรกรรมเสร็จสิ้นแล้ว"* | `REQ-SEC-001`, `REQ-SEC-002` |
