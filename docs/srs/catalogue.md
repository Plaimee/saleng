# บัญชีรายการความต้องการ (`docs/srs/catalogue.md`) — โครงการ Saleng (กลุ่ม 2)

เอกสารนี้รวบรวมความต้องการทั้ง 16 ข้อของกลุ่ม 2 (`REQ-FN-001..006`, `REQ-DAT-001`, `REQ-OP-001..002`, `REQ-SEC-001..002`, `REQ-QA-001..002`, `REQ-UX-001..002`, `REQ-BR-002`) พร้อมเชื่อมโยงหลักฐานที่มา (`EV`) และเกณฑ์การยอมรับ (`AC`)

---

## ตารางบัญชีรายการความต้องการ (Requirements Catalogue — 16 ข้อ)

| รหัส REQ | หมวดหมู่ | ข้อความความต้องการฉบับสมบูรณ์ (Shall Statement) | ที่มา (`EV`) | ลำดับความสำคัญ (MoSCoW) | เกณฑ์การยอมรับ (`AC`) |
|---|---|---|---|---|---|
| `REQ-FN-001` | Functional | ระบบต้องค้นหาใบงานรับซื้อของเก่าสถานะพร้อมรับในรัศมีที่กำหนด (ค่าเริ่มต้น 5 กม.) คำนวณลำดับจุดแวะที่สั้นที่สุด และบล็อกการรับงานเพิ่มหากน้ำหนักสะสมรวมเกินความจุสูงสุดของรถซาเล้ง (`BR-03`) | `EV-01`, `EV-02` | Must Have | `AC-04-01`, `AC-04-02` |
| `REQ-FN-002` | Functional | ระบบต้องให้ซาเล้งบันทึกน้ำหนักชั่งจริงที่หน้างาน (`actual_weight_kg`) พร้อมบังคับแนบรูปถ่ายหน้าตาชั่งดิจิทัล และคำนวณส่วนต่างเทียบกับน้ำหนักประเมินตามกฎ `BR-02` (`±15%`) | `EV-03`, `EV-04` | Must Have | `AC-04-04`, `AC-04-05`, `AC-04-06` |
| `REQ-FN-003` | Functional | ระบบต้องควบคุมการเปลี่ยนสถานะของใบงานตามผังสถานะ `S1..S9` (`MD-STM-04`) และบันทึกพิกัดพร้อมเวลาเมื่อซาเล้งเดินทางถึงหน้างาน (`S3 -> S4`) | `EV-02` | Must Have | `AC-04-01`, `AC-04-03` |
| `REQ-FN-004` | Functional | เมื่อส่วนต่างน้ำหนักชั่งจริงเกิน `±15%` (`BR-02`) ระบบต้องเปลี่ยนสถานะใบงานเป็น `S5 (Re-Quotation Pending)` และส่งยอดเงินใหม่ให้ผู้ขายกดยืนยัน (`S5 -> S6`) หรือปฏิเสธ (`S5 -> S8`) ก่อนชำระเงิน | `EV-04`, `EV-05` | Must Have | `AC-04-06`, `AC-04-07`, `AC-04-08` |
| `REQ-FN-005` | Functional | เมื่อใบงานเข้าสู่สถานะชำระเงินสำเร็จ (`S6 Settled`) ระบบต้องสร้างใบเสร็จดิจิทัล (`DigitalReceipt`) ที่ระบุรหัสอ้างอิงไม่ซ้ำ น้ำหนักชั่งจริง ราคาล็อกต่อหน่วย และยอดชำระสุทธิให้ทั้งผู้ซื้อและผู้ขาย | `EV-05`, `EV-06` | Must Have | `AC-04-04`, `AC-04-07`, `AC-04-09` |
| `REQ-FN-006` | Functional | เมื่อผู้ขายปฏิเสธผลชั่งจริงหรือแจ้งข้อพิพาท ระบบต้องเปลี่ยนสถานะเป็น `S8 (Disputed)` และล็อกข้อมูลภาพถ่ายหน้าตาชั่ง พิกัด GPS และประวัติราคาแบบห้ามแก้ไขเพื่อส่งให้ผู้ดูแลระบบตัดสิน | `EV-04`, `EV-08` | Must Have | `AC-04-08` |
| `REQ-DAT-001` | Data | ระบบต้องจัดเก็บข้อมูลธุรกรรมการชั่งจริง รูปถ่ายหน้าตาชั่ง (ขนาดไม่เกิน 1 MB) รหัส `idempotency_key` และราคาล็อก (`locked_unit_price`) ให้ครบถ้วนสมบูรณ์โดยไม่สูญหาย | `EV-03`, `EV-06` | Must Have | `AC-04-08`, `AC-04-09` |
| `REQ-OP-001` | Operational | ระบบต้องรองรับการบันทึกผลชั่งน้ำหนักและออกใบเสร็จในโหมดออฟไลน์ (`Offline Queue` สูงสุด 50 รายการ / 24 ชม.) และซิงก์ข้อมูลขึ้นเซิร์ฟเวอร์อัตโนมัติแบบไม่เกิดใบเสร็จซ้ำเมื่อสัญญาณกลับมา | `EV-01`, `EV-07` | Must Have | `AC-04-09` |
| `REQ-OP-002` | Operational | หากบริการคำนวณเส้นทางภายนอก (OSRM / Maps API) ไม่ตอบสนองหรือเกิดข้อผิดพลาด ระบบต้องสลับไปใช้สูตรคำนวณระยะทางสำรอง (`Haversine * 1.35`) โดยอัตโนมัติทันที | `EV-02`, `EV-07` | Must Have | `AC-04-10` |
| `REQ-SEC-001` | Security | ระบบต้องบันทึกทุกการเปลี่ยนสถานะใบงาน (`S1..S9`) และการแก้ไขน้ำหนักลงในตาราง `AuditLog` แบบเพิ่มต่อท้ายเท่านั้น (Append-only) พร้อมรหัสผู้กระทำและเวลาประทับ | `EV-08`, `EV-09` | Must Have | `AC-04-08`, `AC-04-11` |
| `REQ-SEC-002` | Security & Privacy | ระบบต้องปกปิดบ้านเลขที่จริงและแปลงเบอร์โทรศัพท์ของผู้ขายเป็นรูปแบบ `08X-XXX-XXXX` (PDPA Masking) ในระหว่างสถานะค้นหา (`S1`) และหลังจากจบงานสมบูรณ์เกิน 24 ชั่วโมง (`S7`) | `EV-08`, `EV-09` | Must Have | `AC-04-01`, `AC-04-11` |
| `REQ-QA-001` | Quality (Performance) | ระบบต้องคำนวณระยะทางและจัดลำดับคิวงาน (ไม่ว่าผ่าน Maps API ปกติหรือ Haversine Fallback) ให้เสร็จสิ้นภายในเวลาไม่เกิน `2.0 วินาที` (P95) | `EV-02`, `EV-07` | Must Have | `AC-04-10` |
| `REQ-QA-002` | Quality (Reliability) | การซิงก์ข้อมูลจากคิวออฟไลน์ (`Offline Sync`) ต้องรับประกันความถูกต้องแบบ Idempotent 100% (อัตราการเกิดใบเสร็จซ้ำเท่ากับ `0%` แม้ส่งคำขอซ้ำจากสัญญาณเน็ตกระพริบ) | `EV-01`, `EV-07` | Must Have | `AC-04-09` |
| `REQ-UX-001` | Usability | ปุ่มดำเนินการหลักบนหน้าจอฝั่งซาเล้งต้องมีความสูงไม่น้อยกว่า `48px` และใช้สีตัดกันชัดเจนเพื่อให้ซาเล้งกดใช้งานด้วยมือข้างเดียวกลางแจ้งได้สะดวก | `EV-01` | Should Have | `AC-04-01` + `ui-review.md` |
| `REQ-UX-002` | Usability | หน้าจอบันทึกน้ำหนักชั่งจริงต้องคำนวณและแสดงเปอร์เซ็นต์ส่วนต่าง (`variance_pct`) พร้อมป้ายสีเตือนทันทีเมื่อเกินเกณฑ์ `±15%` โดยไม่ต้องให้ซาเล้งกดเครื่องคิดเลขเอง | `EV-01`, `EV-03` | Should Have | `AC-04-06` + `ui-review.md` |
| `REQ-BR-002` | Business Rule | ระบบต้องล็อกราคากลางต่อกิโลกรัมของวัสดุแต่ละชนิด ณ เวลาที่ยืนยันนัดหมาย (`Price Snapshot`) และใช้ราคาล็อกดังกล่าวคำนวณยอดชำระแม้ราคากลางประจำวันจะเปลี่ยนในภายหลัง | `EV-04`, `EV-06` | Must Have | `AC-04-12` |
