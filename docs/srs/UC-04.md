# Fully Dressed Use Case Specification (`docs/srs/UC-04.md`) — `UC-04` การจัดการงานและเส้นทางของซาเล้ง

| หัวข้อ | รายละเอียด |
|---|---|
| **รหัสและชื่อ Use Case** | `UC-04`: การจัดการคิวงาน เส้นทาง การชั่งจริงหน้างาน และการออกใบเสร็จดิจิทัล |
| **ผู้ใช้งานหลัก (Primary Actor)** | ซาเล้ง / ผู้รับซื้อรายย่อย (`SH-01`) |
| **ผู้มีส่วนได้เสียอื่น (Secondary Actors)** | ผู้ขายของเก่า (`SH-02`), ผู้ดูแลระบบ (`SH-04`), บริการแผนที่ภายนอก (OSRM / Maps API) |
| **เงื่อนไขก่อนเริ่ม (Preconditions)** | 1. ซาเล้งเข้าสู่ระบบและผ่านการยืนยันตัวตน (KYC Verified) แล้ว (`D-01`)<br>2. มีใบงานที่จับคู่และล็อกราคากลาง ณ เวลานัดหมาย (`S2 Matched`, `REQ-BR-002`) |
| **เหตุการณ์กระตุ้น (Trigger)** | ซาเล้งเปิดหน้าคิวงานในรัศมีและกดปุ่มคำนวณเส้นทางเพื่อเริ่มออกเดินทางรับซื้อของเก่า |
| **ผลลัพธ์หลังจบ (Success Postconditions)** | 1. ใบงานเปลี่ยนสถานะเป็น `S6 (Settled)` และ `S7 (Completed)`<br>2. ออกใบเสร็จดิจิทัลพร้อมซิงก์ข้อมูลสำเร็จโดยไม่ซ้ำซ้อน (`REQ-OP-001`)<br>3. ปกปิดบ้านเลขที่และเบอร์โทรผู้ขายหลังจบงาน (`REQ-SEC-002`) และบันทึก Audit Log (`REQ-SEC-001`) |
| **ผลลัพธ์กรณีล้มเหลว (Failure Postconditions)** | หากผู้ขายปฏิเสธน้ำหนักชั่งจริง ใบงานเปลี่ยนเป็น `S8 (Disputed)` และล็อกภาพถ่ายตาชั่งพร้อมพิกัด GPS ส่งให้ Admin ตัดสิน |

## ลำดับขั้นตอนหลัก (Main Success Scenario — Happy Path)
1. ซาเล้งเปิดดูรายการใบงานในรัศมี 5 กม. ระบบแสดงชื่อซอย/จุดสังเกต น้ำหนักประเมิน และราคาล็อกต่อหน่วย โดยยังซ่อนบ้านเลขที่จริงและเบอร์โทรเต็ม (`REQ-SEC-002`, `AC-04-01`)
2. ซาเล้งเลือกใบงานเข้าคิววิ่ง ระบบตรวจสอบว่าน้ำหนักสะสมรวมไม่เกินความจุรถสูงสุด 200 กก. (`BR-03`, `AC-04-02`)
3. ระบบเรียกบริการแผนที่คำนวณลำดับจุดแวะที่สั้นที่สุดและเวลาถึงโดยประมาณ (ETA) ภายใน 2.0 วินาที (`REQ-FN-001`, `REQ-QA-001`) และเปลี่ยนสถานะเป็น `S3 (En-Route)`
4. เมื่อซาเล้งเดินทางถึงหน้างานในรัศมี 100 เมตรและกดปุ่มถึงหน้างาน ระบบเปลี่ยนสถานะเป็น `S4 (Arrived & Weighing)` พร้อมบันทึกพิกัดและเวลา (`REQ-FN-003`, `AC-04-03`)
5. ซาเล้งชั่งน้ำหนักวัสดุจริง กรอกตัวเลขน้ำหนัก (`actual_weight_kg`) และถ่ายรูปหน้าตาชั่งแนบเข้าสู่ระบบ (`REQ-FN-002`, `REQ-DAT-001`)
6. ระบบคำนวณส่วนต่างน้ำหนักเทียบกับน้ำหนักประเมิน พบว่าไม่เกิน `±15%` (`BR-02`, `AC-04-04`, `AC-04-05`)
7. ระบบคำนวณยอดชำระสุทธิจากน้ำหนักชั่งจริงคูณราคาล็อก ณ เวลานัดหมาย (`REQ-BR-002`, `AC-04-12`) เปลี่ยนสถานะเป็น `S6 (Settled)` ออกใบเสร็จดิจิทัล (`REQ-FN-005`) และเปลี่ยนเป็น `S7 (Completed)`

## ทางเลือกและข้อยกเว้น (Extensions / Alternative & Exception Flows)
- **`A1` (น้ำหนักรวมเกินความจุรถซาเล้ง — ที่ขั้น 2):** หากน้ำหนักรวมเกิน `max_capacity_kg` (เช่น 210 / 200 กก.) ระบบบล็อกไม่ให้รับงานเพิ่มและแจ้งเตือนให้แบ่งเป็นรอบวิ่งถัดไป (`BR-03`, `AC-04-02`)
- **`A2` (ซาเล้งข้ามหรือปฏิเสธใบงานก่อนรับ — ที่ขั้น 1):** ซาเล้งกดข้ามใบงาน ระบบคงสถานะใบงานไว้ให้ซาเล้งคนอื่นในพื้นที่ (`CC-06`)
- **`E1` (ส่วนต่างน้ำหนักชั่งจริงเกิน `±15%` — ที่ขั้น 6):**
  - `E1.1`: ระบบไม่ออกใบเสร็จทันที แต่เปลี่ยนสถานะเป็น `S5 (Re-Quotation Pending)` และส่งแจ้งเตือนยอดเงินใหม่ให้ผู้ขาย (`REQ-FN-004`, `AC-04-06`)
  - `E1.2`: หากผู้ขายกดยอมรับ ระบบเปลี่ยนสถานะเป็น `S6 (Settled)` และทำต่อขั้นที่ 7 (`AC-04-07`)
  - `E1.3`: หากผู้ขายกดปฏิเสธ ระบบเปลี่ยนสถานะเป็น `S8 (Disputed)` และล็อกหลักฐานรูปถ่ายตาชั่งส่งให้ Admin (`REQ-FN-006`, `AC-04-08`)
- **`E2` (อุปกรณ์อยู่ในจุดอับสัญญาณอินเทอร์เน็ต — ที่ขั้น 5–7):** ระบบบันทึกผลชั่ง รูปถ่ายตาชั่ง และใบเสร็จลง `Offline Queue` ในเครื่องพร้อม `idempotency_key` และซิงก์ขึ้นเซิร์ฟเวอร์อัตโนมัติแบบไม่เกิดใบเสร็จซ้ำเมื่อมีสัญญาณ (`REQ-OP-001`, `AC-04-09`)
- **`E3` (บริการแผนที่ภายนอกล่มหรือเกินเวลา — ที่ขั้น 3):** ระบบสลับไปใช้สูตรคำนวณระยะทางสำรอง `Haversine * 1.35` ทันทีภายใน 2.0 วินาที พร้อมแสดงป้ายแจ้งเตือนโหมดสำรอง (`REQ-OP-002`, `AC-04-10`)
