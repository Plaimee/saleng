# Operational, Reliability, Security & Privacy Specification (`docs/srs/operations.md` — ORS)

เอกสารนี้กำหนดข้อกำหนดด้านการปฏิบัติการ (SLI/SLO/SLA), คู่มือรับมือเหตุขัดข้อง (Runbook), การวิเคราะห์ภัยคุกคาม (STRIDE Threat Model), และวงจรชีวิตข้อมูลส่วนบุคคล (PDPA Data Lifecycle) ของโครงการ Saleng (กลุ่ม 2)

---

## 1. ตัวชี้วัดระดับการให้บริการ (SLI / SLO / SLA)

| บริการหลัก | ตัวชี้วัด (SLI) | เป้าหมายภายใน (SLO) | ข้อตกลงระดับบริการ (SLA) | อ้างอิง `REQ` / `AC` |
|---|---|---|---|---|
| **1. การคำนวณระยะทางและจัดคิวงาน (Route & Fallback)** | เวลาตอบกลับ P95 ของ `/api/routes/optimize` | `<= 1.5 วินาที` (ปกติ) และ `<= 2.0 วินาที` (เมื่อสลับใช้ Haversine Fallback) | `<= 2.5 วินาที` ตลอดเวลาทำการ 06:00–20:00 น. | `REQ-QA-001`, `REQ-OP-002`, `AC-04-10` |
| **2. การซิงก์คิวออฟไลน์และออกใบเสร็จ (Offline Sync)** | อัตราความสำเร็จของการซิงก์โดยไม่เกิดใบเสร็จซ้ำ (`Duplicate Receipt Rate`) | ซิงก์สำเร็จ `>= 99.9%` และอัตราใบเสร็จซ้ำ `= 0.0%` | ซิงก์ข้อมูลค้างทั้งหมดภายใน 60 วินาทีหลังสัญญาณกลับมา | `REQ-QA-002`, `REQ-OP-001`, `AC-04-09` |
| **3. ความพร้อมใช้งานของระบบรับงานและชั่งจริง** | สัดส่วนเวลาที่ระบบพร้อมใช้งานรายเดือน (Monthly Uptime) | `>= 99.5%` | `>= 99.0%` (แม้เซิร์ฟเวอร์ล่ม ซาเล้งยังบันทึกผลชั่งใน Offline Queue ได้) | `REQ-OP-001` |

## 2. คู่มือรับมือเหตุขัดข้อง (Operational Runbook)

| เหตุการณ์ผิดปกติ (Incident) | สัญญาณเตือน (Alert Trigger) | ขั้นตอนการรับมืออัตโนมัติของระบบ | ขั้นตอนการปฏิบัติของทีมดูแลระบบ (`SH-04`) |
|---|---|---|---|
| **R1: บริการแผนที่ภายนอก (OSRM / Maps API) ล่มหรือเกินโควตา** | อัตรา HTTP 5xx หรือ Timeout `> 2.0s` เกิน 5 ครั้งใน 1 นาที | สลับใช้ `Haversine * 1.35` ทันที (`REQ-OP-002`), แสดงป้ายแจ้งเตือนบน `UI-04-02`, และบันทึก Audit Log | ตรวจสอบโควตา API Key ของผู้ให้บริการแผนที่ หากล่มยาวเกิน 1 ชม. ให้คงโหมด Haversine จนกว่าจะปกติ |
| **R2: คิวออฟไลน์ของซาเล้งค้างเกิน 24 ชั่วโมง** | พบรายการ `PENDING_OFFLINE` อายุเกิน 20 ชั่วโมงในเครื่องซาเล้ง | แจ้งเตือนบนหน้าจอซาเล้งให้เชื่อมต่อ Wi-Fi/4G เพื่อซิงก์ใบเสร็จก่อนรับงานรอบวันถัดไป (`D-02`) | ตรวจสอบสถานะการซิงก์ในหน้า Admin Dashboard และติดต่อซาเล้งหากมีใบงานค้างในสถานะ `S6` |

## 3. การวิเคราะห์ภัยคุกคามตามกรอบ STRIDE (Threat Model)

| หมวด STRIDE | ภัยคุกคามในบริบท Saleng | มาตรการป้องกันในสเปกและโค้ด | อ้างอิง `REQ` / `AC` |
|---|---|---|---|
| **S — Spoofing (สวมรอยตัวตน)** | บุคคลภายนอกสวมรอยเป็นซาเล้งเพื่อขอดูที่อยู่บ้านผู้ขาย | บังคับผ่าน KYC ก่อนเปิดรับงาน (`D-01`) และซ่อนบ้านเลขที่จริงในหน้าค้นหา (`S1`) | `REQ-SEC-002`, `AC-04-01` |
| **T — Tampering (แก้ไขข้อมูลย้อนหลัง)** | ซาเล้งหรือผู้ขายพยายามแก้ไขตัวเลขน้ำหนักชั่งจริงหรือเปลี่ยนรูปถ่ายตาชั่งหลังเกิดข้อพิพาท | ล็อกหลักฐานทันทีที่เข้าสถานะ `S6/S7/S8` (`BR-01`) และเก็บ `AuditLog` แบบ Append-only พร้อม `payload_hash` | `REQ-SEC-001`, `REQ-FN-006`, `AC-04-08` |
| **R — Repudiation (ปฏิเสธการกระทำ)** | อ้างว่าไม่ได้กดยืนยันราคาใหม่ในสถานะ `S5` หรืออ้างว่าราคากลางเปลี่ยน | บันทึก `actor_id`, `timestamp` ในทุกการเปลี่ยนสถานะ และล็อก `Price Snapshot` ณ เวลานัดหมาย | `REQ-SEC-001`, `REQ-BR-002`, `AC-04-12` |
| **I — Information Disclosure (ข้อมูลรั่วไหล)** | บ้านเลขที่จริงและเบอร์โทรของผู้ขายรั่วไหลในหน้าฟีดสาธารณะหรือค้างหลังจบงาน | ทำ Data Masking (`081-XXX-4567`) ในสถานะ `S1` และหลังจบงาน `S7` เกิน 24 ชั่วโมง | `REQ-SEC-002`, `AC-04-11` |
| **D — Denial of Service (ระบบล่ม/ส่งซ้ำ)** | สัญญาณเน็ตกระพริบทำให้แอปยิงคำขอสร้างใบเสร็จซ้ำรัว ๆ | ใช้ `idempotency_key` ตรวจสอบและจำกัดขนาดรูปถ่ายตาชั่งไม่เกิน `1 MB` | `REQ-OP-001`, `REQ-DAT-001`, `AC-04-09` |
| **E — Elevation of Privilege (ยกระดับสิทธิ์)** | ซาเล้งพยายามเรียก API อนุมัติข้อพิพาท `S8` ด้วยตนเอง | แยก Role-Based Access Control (`Seller`, `Buyer/Saleng`, `Admin`) อย่างเคร่งครัด | `REQ-SEC-001` |

## 4. วงจรชีวิตข้อมูลส่วนบุคคลตามกฎหมาย PDPA (Data Lifecycle)
1. **การเก็บรวบรวม (Collection):** เก็บเฉพาะพิกัดนัดรับ เบอร์โทรศัพท์ และรูปถ่ายหน้าตาชั่งที่จำเป็นต่อการทำธุรกรรมเท่านั้น
2. **การแสดงผลและปกปิด (Masking in Use):** ในสถานะ `S1` แสดงเฉพาะชื่อซอย/จุดสังเกต เปิดเผยบ้านเลขที่เฉพาะซาเล้งที่รับงานในช่วง `S2..S6` และปกปิดกลับเป็น `08X-XXX-XXXX` ทันทีเมื่อพ้น 24 ชม. หลังสถานะ `S7` (`AC-04-11`)
3. **การเก็บรักษาและทำลาย (Retention & Archival):** เก็บประวัติใบเสร็จและหลักฐานข้อพิพาทไว้ตรวจสอบทางบัญชี 90 วัน จากนั้นลบพิกัดละเอียดคงเหลือเฉพาะข้อมูลสรุประดับแขวง/เขต
